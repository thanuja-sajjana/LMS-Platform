# Deploying the LMS on Render

This project includes a Render Blueprint (`render.yaml`) for a free Python web service.

## Free demo limitations

The free service has an ephemeral filesystem and spins down after inactivity. This app stores its SQLite database and private assignment uploads on that filesystem, so **accounts, courses, progress, grades, notifications, and uploaded submissions can be lost when Render spins down, restarts, or redeploys the service**. The app may also take about a minute to wake after inactivity. Use this setup for a demo, not for real student records or important submissions.

For data that must survive, choose a host and storage plan with persistent database and file storage. The previous paid Render disk setup is not enabled in this free Blueprint.

## Before publishing the code

1. Create a **private** GitHub repository and add the project files.
2. Keep `lms.db`, `pass.txt`, `.env` files, and the `uploads/` directory out of Git. The included `.gitignore` excludes them; check the files selected for upload before publishing.
3. The deployed app starts with an empty production database. Local user accounts, courses, enrollments, notifications, and submissions in `lms.db` are not copied. Recreate the courses and invite users after deployment. Do not upload the local database or submissions to a public repository.

## Create the Render service

1. Push the project files to GitHub.
2. In Render, choose **New → Blueprint**, connect the private repository, and select the branch.
3. When prompted for `LMS_ADMIN_USERNAME`, choose your private instructor login name. Set `LMS_ADMIN_PASSWORD` to a strong, unique password. Render generates `SECRET_KEY` automatically.
4. Apply the Blueprint and wait for the build and deploy to finish. Render provides a public HTTPS URL.
5. Sign in using the initial instructor account, create your courses, then share the HTTPS URL.
6. After confirming the instructor account works, remove the `LMS_ADMIN_PASSWORD` environment variable from the Render service and the corresponding `sync: false` entry from `render.yaml`. The account remains in the current database until the free service's filesystem is reset, and instructor self-registration stays disabled.

Render's free web service may be suspended after its included monthly hours are used. Review Render's current free-plan terms and usage limits before deployment. Do not use this free setup as the only copy of important course data or submissions.

## Configuration

The production service requires:

- `APP_ENV=production`
- `SECRET_KEY` (generated by Render; do not put it in source control)
- `LMS_DATA_DIR=/tmp/lms-data` (ephemeral demo storage)
- `ALLOW_INSTRUCTOR_REGISTRATION=false`
- `LMS_ADMIN_USERNAME` and `LMS_ADMIN_PASSWORD` for initial instructor creation
